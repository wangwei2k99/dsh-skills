# 乱码形态与成因对照

本文件是 `SKILL.md` 的补充。用于**反向识别**：看到一段乱码，判断它由哪种错误产生、能否恢复。

## 第一步：判断乱码类型

| 你看到的形态 | 成因 | 可逆 |
|---|---|---|
| `涓枃鍐呭` 这类"看起来像汉字"的怪字 | **UTF-8 字节被按 GBK(cp936) 解码** | 通常可逆 |
| `锟斤拷` | 经两次错误替换（U+FFFD 被再编码） | **不可逆** |
| `?????` 或 `???` | 目标编码无法表示该字符（us-ascii、latin1） | **不可逆** |
| `\u4e2d\u6587` | 未解码的 JSON 转义序列 | 可逆（用 JSON 解析） |
| 显示为方块 □□□ | 字体缺字形，数据本身正常 | 无需恢复 |
| `ä¸­æ–‡` | UTF-8 字节被按 **Latin-1** 解码 | 可逆 |
| 首字符带 `\ufeff` | 文件有 UTF-8 BOM，被当内容读了 | 去掉即可 |

## 三种常见乱码方向

### 方向一：UTF-8 → 按 GBK 解（中文 Windows 最常见）

UTF-8 的 3 字节汉字被 GBK 当成 1.5 个双字节字符，产出一串"伪汉字"。
这是 **PowerShell 5.1 用 `Get-Content` 读无 BOM UTF-8 文件的默认结果**。

修复：读取时显式 `-Encoding utf8`。

### 方向二：UTF-8 → 按 Latin-1 解（跨平台 / 浏览器场景）

产生 `ä¸­æ` 这类形态。修复：按 UTF-8 重新解码。

### 方向三：GBK → 按 UTF-8 解

结果通常是 `�`(U+FFFD) 或直接抛"非法字节序列"异常。**基本不可逆**，
解码时已丢失原始字节。

## 恢复方法（方向一）

原理：把乱码按 GBK 编码回字节，再按 UTF-8 解码。

```powershell
$mojibake = '娴嬭瘯'
$gbk = [System.Text.Encoding]::GetEncoding(936)
$restored = [System.Text.Encoding]::UTF8.GetString($gbk.GetBytes($mojibake))
# => 测试
```

用脚本验证：

```powershell
.\scripts\diagnose.ps1 -MojibakePath .\bad.txt
```

### 为什么推荐走文件而不是命令行参数

用 `-Mojibake "娴嬭瘯"` 传参时，字符串在**到达脚本之前**可能已被 shell 按错误编码
转换过一次。用已损坏的输入做反查，结果自然不对 —— 这恰好就是本技能要诊断的问题
本身，属于"用坏掉的工具检查坏掉的东西"。

实测同样的输入，走命令行参数得到错误结果，走文件读取得到 `测试`（正确）。

## 一个必须知道的限制：本表为什么只有 18 行

原本生成了 25 行，其中 7 行的乱码形态（`中文`、`内容`、`错误`、`路径`、`环境` 等）
**在写入 UTF-8 文本文件时必然损坏**，因此被剔除。原因是这些乱码里含
**GBK 未定义区字符**，.NET 用私用区（U+E000–U+F8FF）填充。私用区字符本身
不是稳定文本，经任何一次"读文本 → 写文本"都会失真。

这带来两个结论：

1. **这类乱码不能靠复制粘贴传播。** 文档、聊天、Issue 里贴出来的乱码可能已经
   与真实字节不同，据此反查会失败。要诊断，必须拿到**原始文件**。
2. **判断可逆性不能看外观。** 私用区字符看起来"损坏更严重"，字节映射其实仍在；
   而 `锟斤拷` 看起来更规整，却已彻底不可逆。

所以判断一律用**回环校验**：

```powershell
$restored = [System.Text.Encoding]::UTF8.GetString($gbk.GetBytes($mojibake))
$reBroken = $gbk.GetString([System.Text.Encoding]::UTF8.GetBytes($restored))
$reversible = ($reBroken -eq $mojibake)   # 只有 $true 才可信
```

`diagnose.ps1` 内部就是这样校验的。

## 什么情况下无法恢复

1. 出现 `锟斤拷` —— 经两次错误转换，原始字节已丢失
2. 出现 `?` —— 目标编码无法表示，编码时就丢弃了信息
3. 出现大量 `�`(U+FFFD) —— 解码用替换而非报错，字节信息已丢
4. 混合了多个方向的转换 —— 无法确定原始路径

**不要对不可逆的情况反复尝试**，直接找原始来源（Git 历史、备份、重新生成）。
